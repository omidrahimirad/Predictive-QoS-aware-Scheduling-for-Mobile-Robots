# Robust scheduling v2 evidence

- `full/`: completed frozen 2,160-run study, eight conditions, 30 independent
  episodes per condition and nine policies including the no-adaptation ablation.
- `quick/`: 144-run exploratory study, two episodes per condition.
- `selection/`: actual predictor validation, residual calibration, development
  threshold selection and pre-evaluation source/config/model freeze.
- `configs/`: exact input configuration; bulk traces and model binaries are regenerated.

Final settings were frozen at db21e0a before the new final seed ranges were executed.
Scientific source remains unchanged after the freeze. Later documentation, CI scope
and the supplementary presentation script do not alter the allocator or statistics.
Manifests honestly retain dirty development states and the clean final freeze.

Run counts are episode-policy executions, not independent sample counts. Conditions
have distinct seeds; policies within each condition share trace hashes. The integrated
ablation reuses those final episodes and is not independent extra evidence.

The six core plots are regenerated by `pqos robust-report`. The seventh deterioration
timeline uses the first predeclared E episode and is regenerated with:

```bash
uv run python scripts/plot_fallback.py --run-dir examples/robust_scheduling_v2/full
```

Historical `examples/verified_run/` remains untouched. `artifact_hashes.json` fingerprints
the numerical/configuration/figure evidence files at delivery; this explanatory README
is not part of that numerical fingerprint ledger. See docs/RESULTS.md for unfavorable
outcomes, throughput trade-offs and unadjusted multiple-comparison limitations.
